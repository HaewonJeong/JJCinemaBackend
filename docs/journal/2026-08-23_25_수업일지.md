## 2026-08-23 (일) — 영화 조회 API 구현

### 오늘 한 일
- `Movie`, `Showtime` 도메인을 조회할 수 있는 REST API의 뼈대를 잡음
- 영화 목록/단건 조회 기능 구현
- 인증이 필요한 API와 아닌 API를 구분하는 보안 설정 정리

### 구현 내용

**1. `SecurityConfig` 정리**
- `/api/auth/**` 는 로그인 없이 허용, 그 외 모든 API는 인증 필요하도록 주석으로 의도 명시

**2. Movie 조회 API**
- `MovieController` 신규 생성 (`/api/movies`)
  - `GET /api/movies` : 전체 영화 목록 조회
  - `GET /api/movies/{movieId}` : 영화 단건 조회
- `MovieResponse` DTO 추가 — `Movie` 엔티티 → 응답 DTO 변환용 `from()` 정적 팩토리 메서드 작성
- `MovieRepository` 추가 (`JpaRepository<Movie, Long>` 상속)
- `MovieService` 추가
  - `getMovies()` : 전체 목록 조회 후 스트림으로 DTO 변환
  - `getMovie(movieId)` : 단건 조회, 없으면 `IllegalStateException("영화를 찾을 수 없습니다.")`

**3. Showtime 관련 준비 작업**
- `ShowtimeRepository` 추가 (`JpaRepository<Showtime, Long>` 상속) — 다음 작업(상영시간표 API)을 위한 선행 작업

### 배운 점 / 메모
- DTO의 `from()` 정적 팩토리 메서드 패턴으로 엔티티 → 응답 변환 로직을 DTO 쪽에 응집시키는 방식을 적용
- 조회 전용 서비스 메서드에는 `@Transactional(readOnly = true)`를 붙여 성능/의도를 명확히 함

## 2026-08-25 (화) — Movie 등록 & Showtime API 구현

### 오늘 한 일
- 영화 등록(생성) 기능 추가
- 상영시간(Showtime) 관련 조회/일괄 수정 API 신규 구현
- `Movie`, `Showtime` 엔티티에 수정용 메서드 추가

### 구현 내용

**1. Movie 등록 API**
- `MovieController` 에 `POST /api/movies` 추가 (`201 Created` 반환)
  - `Authentication` 을 받아 등록자 정보(`createdBy`)를 함께 저장
- `MovieRequest` DTO 신규 작성 (title, genreId, runtime, ratingId, director, releaseDate, posterBase64, synopsis, status)
- `MovieService.create()` 구현 — `Movie.create()` 정적 팩토리로 엔티티 생성 후 저장
- `Movie` 엔티티에 `update()` 메서드 추가 (추후 수정 API를 위한 선행 작업)

**2. Showtime 조회/수정 API**
- `ShowtimeController` 신규 생성 (`/api/showtimes`)
  - `GET /api/showtimes?movieId=` : 특정 영화의 상영시간 목록 조회 (날짜/시간 오름차순 정렬)
  - `GET /api/showtimes/{showtimeId}` : 상영시간 단건 조회
  - `PATCH /api/showtimes/bulk` : 여러 상영시간을 한 번에 상영관/가격 일괄 수정
- `ShowtimeRequest`, `ShowtimeBulkUpdateRequest` DTO 작성
- `ShowtimeResponse` DTO 작성 — 상영시간 정보와 함께 영화 제목(`movieTitle`)도 같이 내려주도록 `from(showtime, movieTitle)` 구현
- `ShowtimeRepository` 에 `findByMovieIdOrderByDateAscTimeAsc(Long movieId)` 쿼리 메서드 추가
- `ShowtimeService` 신규 작성
  - `getShowtimesByMovie()`, `getShowtime()` : 조회 기능, 없으면 `ResponseStatusException(404)` 처리
  - `updateBulk()` : `showtimeIds` 로 여러 건을 조회한 뒤 각각 `update()` 호출하여 일괄 수정
  - 영화 제목 조회를 위한 `getMovieTitle()` 내부 헬퍼 메서드 작성 (영화가 없으면 "알 수 없음" 처리)
- `Showtime` 엔티티에 `update()` 메서드 추가 — 각 필드가 `null`이 아닐 때만 값을 변경하는 부분 업데이트 방식으로 구현

### 배운 점 / 메모
- 예외 처리 방식이 `MovieService`(`IllegalStateException`)와 `ShowtimeService`(`ResponseStatusException`)에서 서로 다르게 사용되고 있음 → 추후 예외 처리 정책 통일 필요 (예: `@RestControllerAdvice` 도입 검토)
- 벌크 수정(`updateBulk`)처럼 여러 필드 중 일부만 선택적으로 바꾸는 경우, 엔티티의 `update()` 메서드에서 `null` 체크로 부분 업데이트를 처리하는 패턴을 적용
- `ShowtimeResponse`에 연관된 `Movie`의 제목을 함께 내려주기 위해 서비스 레이어에서 별도로 `MovieRepository` 를 조회하는 방식 사용 → 데이터가 많아지면 N+1 문제 가능성이 있어, 추후 조인/캐시 방식 개선 여지 있음
